# 酒税申告・年次報告機能 要件定義・差分設計

- 初版: 2026-07-19
- コード再監査・再編: 2026-07-19
- 対象: 既存販売システムへ追加する、1製造場の酒税申告・年次報告機能
- 対象外: 酒蔵の立上げ、製造工程、免許取得・更新、消費税申告書の作成
- 法令上の最終判断: 所轄税務署、酒類指導官または税理士へ確認する

## 1. この設計の境界

### 1.1 税務コアに含める

1. 確定出荷、戻入れ、輸出、未納税移出、社内用途等を酒税申告の根拠として分類する。
2. 月次の酒税納税申告書、税額算出表、控除・免税明細を作成する。
3. 年次の「酒類の販売数量等報告書」を作成する。
4. 担当者確認、責任者承認、PDF・Excel出力、e-Tax転記、提出・受付・納付結果を記録する。
5. 申告値から商品、出荷、返品、販売外在庫出入まで遡れるようにする。

### 1.2 税務コアから外す

次は販売・請求機能の要件であり、本設計では新規設計しない。

- 得意先別の締め日、支払期限、休日補正
- 請求書の消費税計算、適格請求書、郵送・メール配信
- 入金方法、振込先口座、振込手数料、入金消込
- 銀行CSV取込
- 紙証憑の保管場所管理、過去PDFのOCR・自動分類
- 消費税申告書の作成

これらは既存の請求・入金実装を基準とし、必要な改修は別タスクで扱う。税務画面では、酒税判断に必要な消費税区分を参照表示するだけとする。

### 2.3 誤って新規設計していた部分

次の案は採用しない。

- `customer_billing_terms`: 既存の`billing_cycles`と重複する。
- `payment_methods`, `deposit_accounts`, 新しい`payments`: 既存の入金機能と重複する。
- `dispatch_status`: この蔵では出荷確定日が門を出た日であり、既存の出荷確定を課税移出確定として使う。
- 汎用`tax_transaction_types`の全面新設: 通常販売、輸出、自家用は既存の`settlement_receivable_categories`を拡張する。
- 高度な`tax_documents`: 初期段階では証憑状態、種別、識別番号、摘要で足りる。ファイル添付は後続とする。
- 過去PDFのOCR・自動関連付け: 初期移行の必須要件にしない。

### 2.4 再検証結果

次のFeature TestをテストDBで実行した。

- `MonthlyLiquorTaxTransferAggregationTest`
- `InvoiceTaxRoundingTest`
- `RegisterPaymentTest`
- `SalesReturnTest`
- `NonSalesStockOperationTest`

結果は17件中1件成功、16件失敗だった。`NonSalesStockOperationTest`は成功した。残りは、出荷確定前のロット引当不足または商品とロットの単位不一致で停止しており、月次酒税集計、請求税計算、入金、返品の本来のアサーションまで到達していない。

これは該当機能が未実装であることを直接示す失敗ではないが、ロット中心在庫への変更後に回帰テストが保守されていないことを示す。税務機能の実装前に、既存テストのロット作成・引当条件を現在の仕様へ合わせ、基礎機能が通る状態へ戻す必要がある。本設計では、コードが存在する機能と、テストで動作保証された機能を区別する。

## 3. 確定した業務条件

| 項目 | 決定内容 |
|---|---|
| 事業主体 | 有限会社 |
| 管理単位 | 当面1製造場・1蔵1環境 |
| 将来 | 他蔵への独立導入を可能にし、将来の複数蔵対応を妨げない |
| 酒類 | 清酒、リキュール |
| 商品 | 1商品1アルコール分。原酒・低アルコール酒は別商品 |
| 容量 | 180ml、300ml、330ml、720ml、1,800ml、4,500ml |
| 酒類外 | 酒粕、食品、グッズ、送料が酒類と同じ伝票に混在する |
| 課税移出日 | 出荷伝票日を初期値とし、出荷確定時に担当者が変更可能 |
| 伝票内の税務区分 | 通常課税・輸出免税・未納税移出等が1伝票内で混在することはない。受注・出荷ヘッダ単位で管理する |
| 委託倉庫 | 蔵置所扱い。製造場から搬出した時点で課税移出。倉庫から販売出荷はしない |
| 委託倉庫の伝票 | 委託倉庫を出荷伝票の得意先として指定する。課税移出には含めるが、年次販売数量の販売先には含めない |
| 委託倉庫への請求 | 請求書を発行しない。酒税上は課税移出、販売・売掛上は非売上として扱う |
| 委託倉庫向け金額 | 商品単価・金額は入力するが参考値とし、売上・売掛・請求を発生させない |
| 返品 | 元伝票へ反対伝票を紐付け、複数回の部分戻入れを許容。戻入れ月で控除 |
| 輸出 | 自社が輸出者となる直接輸出と、国内商社による間接輸出 |
| 未納税移出 | 他社製造場へ原料用・加工用として移出 |
| 未納税移出の請求 | 販売取引として相手先へ請求書を発行する。酒税のみ未納税移出、国内販売の消費税は10%として扱う |
| 未納税移出の証明 | 移出先製造場へ実際に移入されたことを証明する書類を保有している |
| 社内用途 | 自家用、無償提供、贈答、試飲、検査提出。請求なしの出荷伝票・納品書を作成 |
| 社内用途の消費税 | 通常は課税対象外。役員個人への贈与等は税務担当者が例外調整し個別承認 |
| 廃棄 | 製造場または保管倉庫で実施。50L以上を初期警告基準とする |
| 酒税軽減 | この蔵は旧制度計算方式。導入先ごとに旧・新を初期選択し、旧から新へは前年度3月31日までの取止届出に基づく翌年度移行のみ許可。新から旧へは戻せない |
| 月次フロー | 販売担当が出荷締め -> 税務担当が集計・例外確認 -> 責任者承認 -> 代表者がe-Tax送信 |
| 送信後 | 元申告を変更せず、修正申告・更正請求を別版として管理 |
| 出力 | e-Tax転記用の画面、PDF、Excel。Excel上の変更はシステムへ自動反映しない |
| e-Tax | Windows版。初期は転記、次に取込ファイル、直接送信は将来検討 |
| 年次店舗データ | 蔵の店は別管理。手入力とExcel/CSV取込を用意し、期間単位で全件置換 |
| 権限 | システム管理権限と申告作成・承認権限を分離 |
| 保存 | 物理削除しない。取消・差替え・修正は履歴を残す |

## 4. 法定帳票と保持内容

### 4.1 月次酒税申告

原則として、移出等があった月の翌月末日までに製造場ごとに提出する。

| 帳票・明細 | 主な保持内容 | 優先度 |
|---|---|---|
| 酒税納税申告書 | 対象月、製造場、課税標準、算出税額、控除、免除、納付税額 | 必須 |
| 税額算出表 | 酒類、税率適用区分、数量、税率、軽減、税額 | 必須 |
| 軽減税額算出表 | 適用制度、年度累計、限度、軽減額 | 必須 |
| 戻入れ控除計算 | 戻入日、元移出、税率区分、数量、控除額 | 必須 |
| 未納税移出 | 移出先製造場、移出日、移入確認、数量、証明状態 | 必須 |
| 輸出免税 | 輸出日、仕向地、税関、輸出者、数量、証明状態・識別番号 | 必須 |
| 手動調整 | 増減数量・税額、理由、承認 | 必須 |
| 被災・再移出等 | 事象、数量、確認書、控除・還付 | 将来拡張 |

税額は、出荷明細で計算済みの見込税額を単純合算しない。法定の税率適用区分ごとに月間数量を集計して税額を計算し、1円未満を処理した後、控除後の納付額について100円未満を処理する。計算規則バージョンを保存する。

### 4.2 年次報告

「酒類の販売数量等報告書」は4月1日から翌年3月31日を対象とし、原則4月30日までに提出する。

| 公式項目 | 集計方法 |
|---|---|
| 酒類区分 | 清酒、リキュール等 |
| 対卸売業者 | 他製造者・卸売業者への販売数量 |
| 対小売業者 | 酒類小売業者への販売数量 |
| 小売販売 | 消費者、飲食店、ホテル等への販売数量 |
| 3月末在庫 | 報告対象場所の年度末在庫 |

輸出数量は国内の卸売・小売販売数量へ含めず、返品を差し引く。都道府県別・容器容量別は公式列ではなく、確認用ドリルダウンとする。

### 4.3 帳票生成方針

帳票の正本となる様式・項目定義は、国税局ごとの独自資料ではなく、国税庁およびe-Taxが公開する公式様式・仕様から取得する。ただし、公式PDF自体を申告データの保存先にはしない。システム内部の確定申告データと帳票レイアウトを分離する。

1. 月次の初期実装は、国税庁の酒税申告様式と同じ項目名・順序によるe-Tax転記画面、確認用PDF、作業用Excelを生成する。実際の提出はWindows版e-Taxで行う。
2. システムが生成するPDFは印刷・転記確認用とし、ファイルを恒久保存しない。紙で保管する現在の運用を継続し、必要な場合は確定申告データと当時の帳票定義から同じPDFを再生成する。e-Taxが生成する公式帳票PDFもシステムへ取り込まない。
3. 年次報告は、国税庁が配布する「販売数量報告書等作成補助ツール」および一括入力データの形式を優先する。
4. 将来のe-Tax取込ファイルはPDFから変換せず、e-Taxが公開する酒税XML構造設計書・帳票フィールド仕様書の該当バージョンから生成する。
5. 帳票定義には、帳票名、適用開始日・終了日、公式版番号、取得元URL、取得日、SHA-256、対応する計算規則バージョンを保存する。公式様式が更新されても自動更新せず、差分確認と回帰テスト後に有効化する。
6. 出力履歴には、使用した帳票定義、申告版、出力日時、操作者、形式、SHA-256を記録する。生成ファイルそのものは保存せず、後日の様式変更によって過去出力を再解釈しない。

### 4.4 2026年改正への対応

2026-07-19時点で、国税庁は2026年9月以後使用する差額課税関係様式を公開し、e-Taxは2026年9月24日受付開始予定のKSK2対応仕様をドラフト公開している。確定前に変更される可能性があるため、e-Tax取込ファイルの最終実装は確定仕様の公開後に行う。

- 2026-10-01以後も清酒の基本税率は100,000円/klであり、現在の商品構成では清酒に差額は生じない。
- Access上のリキュール商品は1件、アルコール分19.4度であり、2026-10-01の低度数リキュール税率変更の影響外である。
- 現行商品だけを前提とする限り、差額課税・手持品課税の専用画面は初期実装へ含めない。将来、改正対象商品を登録した場合は、適用日前在庫の確認警告を出し、専用帳票を追加できる構造にする。
- 税率マスタは2026-09-30で打ち切らず、公式税率を有効期間付きで登録する。商品登録時には酒類、発泡性、アルコール分から該当税率を検証する。

## 5. 現行実装との差分

### 5.1 P0: 月次申告の正確性に必要

1. **取引区分の判定を出荷確定へ接続する**
   - `settlement_receivable_categories`には輸出・自家用の属性があるが、`ConfirmShipmentService`は商品マスタだけから消費税・酒税を解決している。
   - 既存カテゴリを優先するResolverへ変更し、直接輸出、間接輸出、未納税移出、通常課税、社内用途を確定スナップショットへ保存する。
2. **酒税ルールを実運用分まで完成する**
   - Seederには清酒の基礎ルールしかなく、リキュールのアルコール分別ルールがない。
   - 清酒ルールの登録期間も2026-09-30までのため、その後を含む有効期間を公式値で整備する。
3. **軽減計算を旧制度・新制度の選択式にする**
   - 現状は各酒税ルールの固定`reduction_rate`を明細税額へ掛けている。
   - この蔵は旧制度を初期値とし、旧制度の品目別累計数量による計算を実装する。
   - 導入先ごとに初期方式を選択できるようにし、新制度の年度累計軽減前税額による計算も別エンジンとして実装する。
   - 旧制度から新制度への変更は、前年度3月31日までの取止届出に基づく翌年度開始の設定変更とする。年度途中の切替、新制度から旧制度への復帰、確定済み期間の遡及再計算を禁止する。計算方式、適用年度、届出日、計算規則バージョンを申告スナップショットへ保存する。
4. **戻入れ・販売外移動を申告へ接続する**
   - 返品・販売外在庫出入と酒税スナップショットはあるが、月次申告集計は確定出荷しか見ていない。
   - 戻入れ控除、自家用等の課税移出、廃棄を申告根拠へ統合する。
5. **法定単位で再計算する**
   - 現状は出荷明細の`confirmed_liquor_tax_estimated_amount`を合算している。
   - 税率適用区分別の月間数量から申告税額を再計算する。
6. **申告根拠スナップショットを追加する**
   - 申告確定時点の元取引ID、数量、税率、軽減、税額を固定し、マスタ変更後も再現可能にする。

### 5.2 P1: 申告業務を完結するために必要

1. 原申告、修正申告、更正請求の版管理。
2. 控除、免税、手動調整、差異理由の構造化。
3. PDFとExcelによるe-Tax転記表。現状の固定TXTは内部確認用に留める。
4. 提出日時、受付番号・結果、納付日・方法・金額の記録。
5. 年次販売数量報告のDB、API、画面、店舗データ取込。
6. 得意先の法定販売先区分と都道府県コード。
7. 在庫場所の税務区分と、年次在庫への算入可否。

### 5.3 P2: 後続で追加

- 税務ダッシュボードと期限通知

## 6. データ設計

### 6.1 既存テーブルを拡張する

#### `settlement_receivable_categories`

既存の`export_type`、`liquor_tax_type`、`consumption_tax_type`を利用する。必要に応じて次を追加する。

- `liquor_tax_treatment`: `taxable`, `export_exempt`, `untaxed_transfer`, `not_applicable`
- `requires_tax_review`, `requires_evidence`
- 委託倉庫搬出用の区分は`liquor_tax_treatment = taxable`、`receivable_method = none`、`invoice_required = false`とする
- 未納税移出用の区分は`liquor_tax_treatment = untaxed_transfer`、`consumption_tax_type = taxable`、`receivable_method = accounts_receivable`、`invoice_required = true`とする。酒類の消費税率は10%とする
- 単価・金額の有無ではなく売掛・精算区分によって売上・請求対象を判定する
- 直接・間接輸出の別は出荷側の例外情報で保持する
- 受注時に既存の`sales_orders.settlement_receivable_category_id`を選び、出荷作成時に`shipment_headers`へ引き継ぐ。明細ごとの重複区分は追加しない

#### `shipment_headers`

- 既存の`liquor_tax_transfer_date`を課税移出日に使う
- 新しい搬出状態は追加せず、既存の出荷確定を課税移出確定とする
- `confirmed`後の課税移出日は変更不可。締め前の訂正は取消・再作成、締め後は調整・修正申告で扱う
- 例外取引用に、輸出方式、輸出者、仕向地、税関、証憑種別・番号・確認状態を追加する

#### `shipment_lines`

- 既存の`confirmed_*`を再利用する
- ヘッダの税務取引区分、酒税上の扱い、根拠となった売掛・精算区分を確定時に各明細のスナップショットへ追加する
- 酒税対象商品で容量、容量単位、アルコール分、酒税区分が不足する場合は確定不可

#### `liquor_tax_monthly_filings`

既存テーブルを置き換えず、次を追加する。

- `tax_premise_id`
- `filing_type`: `original`, `amended`, `claim_for_correction`
- `original_filing_id`, `version_no`, `due_on`
- 控除額、免除数量、確定納付額
- `calculation_rule_version`
- 作成・確認・承認・出力・提出・受付・納付の各日時と担当者
- 一意制約を製造場・対象年月・申告種別・版番号の組合せへ変更する

#### `customers`

- `prefecture_code`
- `legal_sales_destination_type`: `manufacturer`, `wholesaler`, `retailer`, `on_premise_business`, `consumer`, `export_trader`, `government`, `internal`, `other`

#### `stock_locations`

- 既存の`location_type`, `is_tax_relevant`を利用する
- `tax_location_type`: `manufacturing_premise`, `tax_paid_storage`, `approved_storage`, `retail_store`, `other`
- `included_in_annual_stock`

#### `tax_premises`

#### `liquor_tax_adjustment_lines`

- 増減数量、増減税額、理由、根拠

#### `retail_sales_import_batches` / `retail_sales_import_rows`

- 対象申告・報告、提出方法、提出日時、受付番号、受付日時、受付結果

#### `liquor_tax_payment_records`

## 8. 税務画面

### 8.1 税務ダッシュボード

### 8.2 月次申告詳細

画面を過度に分割せず、次の5タブとする。

1. `申告書`: e-Tax転記順の数値、PDF・Excel出力
2. `根拠`: 酒類・税率 -> 商品 -> 出荷・販売外移動

警告が残る場合でも、理由を入力すれば確定・出力できる。ただし手動調整は責任者承認を必須とする。

- 酒類区分別の対卸売、対小売、小売、3月末在庫

- PDF、国税庁作成補助ツール用データ、提出結果

PCとタブレットに対応する。確定申告データをシステム上の正本とし、PDFは紙保管・確認用に都度生成、Excelは確認・転記用とする。

- `酒税区分`と旧来の個別フラグが一致しない伝票が677件ある。主に輸出区分と`酒税未納取引`の併用であり、移行判定は`酒税区分`を優先しつつ全原値を保存して警告する。

- 2023-10-01以後の清酒明細には税率100,000円/kl、軽減率80%が保存されており、旧制度運用の移行根拠として保持する。

### 11.3 移行対象

税務コアに関係する移行対象:

- 得意先、商品、出荷、出荷明細
- 戻入れ・伝票外在庫出入
- 酒税区分、酒税率、軽減率、過去酒税集計
- 移行元ID、元テーブル名、移行バッチID

販売システム全体の移行対象だが税務コア外:

- 入金履歴
- 得意先別の開始売掛残高
- 過去消費税額

方針:

1. 全履歴を通常検索対象として移行する。
2. 過去税額は当時の確定値を保存し、現在の税率で再計算しない。
3. 区分・フラグ・摘要が矛盾する行は自動確定せず警告する。
4. 最新Accessコピーで本番再取込し、件数・数量・税額を照合する。
5. 過去申告は紙保管であり、e-Taxから必要時にPDF出力できるため、過去PDFの移行機能は作らない。
6. 過去のe-Tax受付結果と納付証憑は移行しない。
7. 実データ入りAccessファイルはリポジトリや通常バックアップへ含めず、移行ジョブの入力元パスとSHA-256だけを監査記録へ保存する。

## 14. 主要受入テスト

1. 清酒・リキュール、複数容量、非酒類混在の通常課税移出。

6. 申告確定済み月の出荷確定・取消・移出日変更を拒否する。
7. 旧制度と新制度の軽減計算、年度途中導入時の累計引継ぎ、翌年度からの旧から新への不可逆切替、年度途中切替の拒否。

9. 申告値から商品・出荷・戻入れ・販売外移動へ遡れる。
10. 手動調整に個別承認がなければ確定できない。
11. 送信後の修正申告で元版が変わらない。
12. 年次販売数量から輸出を除外し返品を控除し、3月末在庫を加える。
13. 店舗取込は1件のエラーで全件不成立となり、再取込で対象期間を全件置換する。
