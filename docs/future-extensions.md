# 将来拡張方針

## 1. 位置づけ

第14段階は、本番運用試験前に本体機能へ追加実装する工程ではなく、将来拡張の境界と判断条件を整理する工程とする。

対象は以下とする。

* 会計連携
* 仕訳出力
* 会計ソフト向けCSVまたはAPI出力
* 製造管理システム連携
* 原価参照
* BI分析
* AI分析
* 音声操作

## 2. 運用試験前の扱い

運用試験前には、将来拡張のためだけに本体DB、月次締め、税務確定、帳票、承認フローへ新しい実装を追加しない。

運用試験前に行うことは以下に限定する。

* 将来拡張として扱う対象を明記する。
* すぐ実装しない対象を明記する。
* 将来参照する元データを壊さない方針を確認する。
* 本番運用試験後に実装判断する条件を残す。

## 3. 会計連携の扱い

会計連携は、運用試験後に必要性、対象会計ソフト、出力形式、勘定科目体系、税区分、部門、補助科目、締め単位を確認してから実装判断する。

現時点では以下を実装しない。

* 仕訳テーブル
* 会計ソフト向けCSV出力
* 会計ソフト向けAPI連携
* 仕訳生成ジョブ
* 会計連携用の締め処理

ただし、将来の会計連携で必要になる元データは、既存の確定済み業務データから参照できる状態を維持する。

参照元の候補は以下とする。

* 確定済み出荷
* 確定済み請求
* 入金、入金消込
* 売掛月次残高
* 酒税月次申告
* 消費税月次申告
* 在庫移動
* 在庫月次残高
* 取消、訂正、調整の履歴

## 4. 製造管理システム連携の扱い

詳細な製造管理、原価管理、ブレンド、火入、瓶詰、移送は販売管理本体へ取り込まない。

販売管理側では、将来連携のために以下の参照情報を保持できれば足りる。

* 製造ロットID
* 製造システム連携ID
* 外部参照キー
* ロット表示名

製造管理連携の実装は、実運用で必要な連携先、連携頻度、責任分界、原価参照方法が確定してから判断する。

## 5. BI、AI、音声操作の扱い

BI分析、AI分析、音声操作は本体業務データの整合性より優先しない。

実装判断は以下を確認してから行う。

* 参照対象データが確定済みか。
* 個人情報、取引先情報、価格情報の扱いが明確か。
* 監査ログ、権限、出力制御の対象にできるか。
* 本体DBへ誤った更新を行わない構造にできるか。

## 6. 後付け可能性

第14段階の対象は、運用試験後に後付け可能とする。

後付け可能とする条件は以下である。

* 確定済み業務データが履歴として保存されていること。
* 出荷、請求、入金、税務、在庫、月次残高が直接上書きされないこと。
* 取消、訂正、調整が差分レコードとして残ること。
* 帳票、監査ログ、承認履歴が追跡可能であること。
* 連携処理が既存の月次締めや税務確定を破壊しないこと。

## 7. 運用試験後の判断条件

運用試験後に以下を確認してから、第14段階の実装有無を決める。

* 会計ソフト連携が本当に必要か。
* 手入力、CSV出力、API連携のどれが現実的か。
* 勘定科目、補助科目、税区分、部門の運用が決まっているか。
* 製造管理システムとの連携責任範囲が決まっているか。
* BI、AI、音声操作に使うデータ範囲と権限が決まっているか。
* 実装によって本体運用の安定性を落とさないか。
