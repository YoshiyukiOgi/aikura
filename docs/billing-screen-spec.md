# 請求・入金画面仕様

## 画面構成と作業順

- 左サイドバーには業務カテゴリとして「請求・入金」だけを置き、カテゴリ内の機能は画面上部のタブで切り替える。
- タブは日常業務の流れに合わせ、`月次請求` → `都度請求` → `請求一覧・確定` → `請求書印刷` → `入金確認` → `要確認入金` → `売掛残高` の順に固定する。
- `/billing` を開いた場合は、最初の作業である「月次請求」を表示する。
- 各機能は個別URLを維持し、どの機能を開いても同じ位置・同じ順序の上部タブを表示する。
- 今後の業務画面も「左サイドバー＝業務カテゴリ、上部タブ＝カテゴリ内機能」を標準とし、タブは `作成・入力` → `確認・確定` → `帳票出力` → `照合` → `例外処理` → `残高・履歴確認` の作業順に並べる。

## 請求対象

- 画面は `GET /api/v1/billing/billable-shipments` だけを候補として表示する。
- 出荷確定済みで、取消済み以外の請求書明細に未紐付けの出荷が対象である。
- 複数選択は同一取引先に限る。請求対象日の期間指定には `billing_target_date` を用いる。

## 請求

- 下書き請求書は確定できる。
- 確定済み請求書からのみ入金予定を作成できる。
- 請求取消には理由を必須とする。
- 一覧・詳細には税抜額、消費税額、税込額を表示する。

## 入金

- 入金は入金予定へ充当する。
- 入金額が残額を超える場合、超過分は未充当額として保存され、入金状態は `review_required` になる。
- `review_required` は要確認として画面上で強調する。
- 入金取消には理由を必須とする。
