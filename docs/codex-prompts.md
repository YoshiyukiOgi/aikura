# Codex依頼方針

## 1. 基本方針

1. 依頼は小さな工程単位に分ける。
2. 実装対象、確認観点、関連ドキュメントを明示する。
3. 実装後はテストとマニフェスト整合を確認する。
4. 巨大な一括生成を避ける。

## 2. 良い依頼例

* `5-11 売掛月次残高ドラフトを実装して`
* `酒税申告確定済み期間制御のテストを追加して`
* `マニフェストと実装の整合チェックをして`
* `8-1 Controller/API基礎を実装して`
* `8-2 権限制御の接続テストを追加して`
* `9-1 請求書PDF固定保存を強化して`

## 3. 禁止したい依頼

* 全機能を一括で作る依頼
* テストなしで中核処理だけ追加する依頼
* 確定済みデータを直接書き換える依頼
