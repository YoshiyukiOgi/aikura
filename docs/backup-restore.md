# バックアップ・復元方針

## 1. 対象

* PostgreSQLデータベース
* 発行済み帳票ファイル
* 添付ファイル
* 設定ファイル

## 2. 基本方針

1. DBとファイルの整合が取れたバックアップを取得する。
2. 世代管理を行う。
3. 定期的に復元テストを行う。
4. 復元手順を文書化する。

## 3. 第5段階時点

運用方針のみ定義し、自動バックアップ実装は後続段階で扱う。

## 4. 最重要システム起点バックアップ

2026-08-21時点の最優先かつ恒久保護対象のDB復元点を次のとおり指定する。

| 項目 | 内容 |
| --- | --- |
| ファイル | `backups/aikura_permanent_baseline_20260821_1555.dump` |
| 作成日時 | 2026-08-21 16:15:26 JST |
| 対象 | 蔵システム・小売システムが共用するPostgreSQLデータベース全体 |
| 位置付け | 2026-08-21時点の現行運用状態を固定するシステム起点 |
| SHA-256 | `0B85C55545666477E4E3C2C587ACC776052741176F34F0762EB1A5436E71A003` |
| 個別台帳 | `backups/aikura_permanent_baseline_20260821_1555.manifest.txt` |

このバックアップは通常の世代整理、ローテーション、容量整理の削除対象にしない。後日作成された通常バックアップが存在しても、この指定は明示的な変更記録なしには解除されない。

復元前にはSHA-256を照合し、可能な限り別の検証用データベースへ復元して内容を確認する。本バックアップを稼働DBへ復元すると、作成日時より後に行われた蔵・小売双方のDB変更が失われるため、実行直前にも別途最新バックアップを取得する。

本指定はDBデータのみを対象とする。アプリケーションコード、Access移行元、PDF、発行済み帳票、添付ファイルは別管理とする。
