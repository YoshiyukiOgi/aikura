# Accessデータ移行

## 1. 現在の完成範囲

Access移行は次の段階まで実装済みである。

1. Windows上の`.accdb`をSHA-256計算後に作業領域へ一時コピーする。
2. ACE OLE DBを読取専用モードで開き、全テーブルをUTF-8 NDJSONへ抽出する。
3. 原本情報、テーブル定義、行数、各NDJSONのSHA-256を`manifest.json`へ保存する。
4. 販売・税務に必要な16テーブルを1トランザクションでステージングする。
5. 件数、参照整合性、既知の例外を検証し、エラーと警告を記録する。

通常の販売テーブルへの確定取込は、得意先・商品マスタ、出荷履歴、戻入れ・伝票外在庫出入まで実装済みである。ステージングした原値から、次は入金を変換し、対象別の照合を追加してから確定する。

## 2. 実行方法

Windows PowerShellでプロジェクトルートから実行する。

```powershell
.\scripts\access\Stage-AccessMigration.ps1 -SourcePath 'C:\Users\ogich\OneDrive\デスクトップ\Itaro-xp.accdb'
```

このコマンドは抽出、ステージング、検証を順に実行する。個別に実行する場合は次を使用する。

```powershell
.\scripts\access\Export-AccessMigrationPackage.ps1 -SourcePath 'C:\path\to\Itaro-xp.accdb'
docker compose exec -T app php artisan aikura:access-stage storage/app/access-migrations/<package>
docker compose exec -T app php artisan aikura:access-validate <batch-id>
docker compose exec -T app php artisan aikura:access-import-masters <batch-id>
docker compose exec -T app php artisan aikura:access-import-shipments <batch-id>
docker compose exec -T app php artisan aikura:access-import-inventory-history <batch-id>
```

## 3. 全件取込の原則

- 原本Accessは更新しない。一時コピーは抽出終了時に削除する。
- 原本ファイル自体はリポジトリ、移行パッケージ、通常バックアップへ含めない。
- 抽出パッケージは`storage/app/access-migrations`に置き、Git管理外とする。
- 原本パス、サイズ、更新日時、SHA-256を移行バッチへ記録する。
- NDJSONのハッシュ、行数、移行元キーのいずれかが不正なら、そのバッチのステージング行をすべてロールバックする。
- 再実行は既存バッチの上書きではなく、新しい移行バッチとして行う。
- 警告行は除外・補正せず、Accessの原値を保持する。
- 過去の酒税・消費税は当時値を移行し、現行税率で再計算しない。

## 4. ステータス

| 状態 | 意味 |
|---|---|
| `staging` | ステージング中 |
| `failed` | ハッシュ、行数、キーなどの異常により全件ロールバック |
| `staged` | 原値のステージング完了、検証前 |
| `blocked` | 参照切れなどのエラーがあり確定取込不可 |
| `ready_with_warnings` | エラーなし。原値を保持すべき警告あり |
| `ready` | エラー・警告なし |
| `masters_imported` | 得意先・商品マスタの業務テーブル取込完了 |
| `shipments_imported` | 過去出荷ヘッダー・明細の確定取込完了 |
| `inventory_history_imported` | 戻入れ確認・伝票外在庫出入の履歴取込完了 |
