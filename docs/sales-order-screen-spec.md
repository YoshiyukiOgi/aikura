# 受注画面 仕様（初期版）

最終更新: 2026-06-21

## 1. 目的

受注を登録し、後続の出荷指示・品出・出荷へ渡す。受注作成時点では、在庫移動、請求、売掛、税額の確定を行わない。

## 2. 初期版の画面構成

- 受注一覧
- 新規受注フォーム
- 商品明細
- 明細単価の価格根拠・今回のみの単価変更

## 3. 保存する受注項目

| 画面項目 | API/DB項目 | 必須 |
| --- | --- | --- |
| 取引先 | `customer_id` | 必須 |
| 受注日 | `order_date` | 必須 |
| 希望納品日 | `requested_delivery_date` | 任意 |
| 取引先注文番号 | `customer_order_number` | 任意 |
| 備考 | `note` | 任意 |
| 商品 | `sales_order_lines.product_id` | 必須 |
| 数量 | `sales_order_lines.quantity` | 必須 |
| 単位 | `sales_order_lines.unit_id` | 必須 |
| 適用単価 | `sales_order_lines.unit_price` ほか価格スナップショット | 価格適用後 |

`requested_shipment_date`、`billing_target_date` はAPIで受け付けるが、初期画面には表示しない。

## 4. 表示しない項目

以下は保存先または業務仕様を追加するまで、受注作成画面に表示しない。

- お届け先
- 支払条件
- 納品方法
- 担当者
- 自分の受注のみ

## 5. 受注状態

画面表示と内部値は次で固定する。

| 表示 | `sales_orders.status` |
| --- | --- |
| 受注済み | `received` |
| 一部出荷指示済み | `partially_instructed` |
| 出荷指示済み | `instructed` |
| 取消 | `cancelled` |

初期版に下書き状態は設けない。受注作成は `received` として登録する。

## 6. 価格

- 価格適用は、取引先価格、取引区分価格、共通/標準価格の優先順で解決する。
- 受注登録APIは明細ごとに価格を適用する。適用できる価格がない明細を含む受注は、登録せず業務エラーとして返す。
- 明細の「今回のみ変更」は、単価・根拠・理由・日時を受注明細へ保存する。
- 例外単価を解除する操作名は「適用価格に戻す」とする。
- 「適用価格に戻す」は、対象明細に対し価格解決を再実行する。
- 取引先価格そのものを変更する操作は、価格マスタの `price_rules` を更新する。

## 7. 金額表示

小計、消費税、合計は初期版では参考表示とする。請求額・税額・売掛額として確定しない。

- 画面上では「参考金額」と明示する。
- 明細の数量または単価変更時に参考金額を再計算する。
- 請求確定・税確定は出荷伝票・請求の後続業務で行う。

## 8. 初期版の対象外

- 受注下書き
- 受注ごとの配送先・納品方法・担当者
- 担当者別の受注一覧
- 受注一覧のサーバー検索・ページング
- 受注金額・消費税・売掛の確定

## 9. 実装完了条件

1. 画面項目が第3章のAPI/DB項目へ保存される。
2. 状態表示が第5章の対応表と一致する。
3. 下書き保存を表示しない。
4. 明細価格の適用、今回のみ変更、適用価格への復帰が監査ログ付きで動作する。
5. 参考金額であることを画面に明示する。
