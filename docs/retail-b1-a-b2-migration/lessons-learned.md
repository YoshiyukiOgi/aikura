# 小売移行へ引き継ぐ知見

小売移行は未実行。本書は [酒蔵移行の知見](../brewery-b1-a-b2-migration/lessons-learned.md) と、今回の小売準備調査を区別して整理したもので、小売での成功実績を示すものではない。

## 酒蔵移行から引き継ぐこと

1. B1原値・警告・除外理由を保全し、移行先の残高を推測で作らない。
2. 差分には追加だけでなく変更・削除・明細差し替えがある。既存請求・消込・月次への参照を確認する。
3. Aの適用前状態を固定し、隔離DBで同じ処理と再実行・復旧を確認する。
4. 取引日、請求年月、入金日を混同しない。台帳の符号だけで実入金・返金と判断しない。
5. 過去の金額・税額と端数の計算単位を尊重し、現在の商品価格・税率で履歴を作り直さない。
6. A→B2はコード・DB・帳票・添付を一組として完全昇格する。差異はAで修正する。
7. Gitコミットと配布アーカイブのSHA-256で同一性を確認する。Windows/Linuxの改行差による展開済みファイルの差を配布版の差と混同しない。
8. 日本語ファイル名を含むアーカイブは、酒蔵移行で得た展開方法を参考にB2側で復元し、件数・必要ファイルの表示を確認する。
9. 対象サービスだけを停止し、起動に必要なイメージを事前確認する。コンテナ起動だけで合格にせず、HTTP・ログ・migration・ジョブを確認する。
10. 過去のバッチ・承認・バックアップ省略を次回へ流用しない。実行結果と復旧結果を各回の記録へ残す。

## 小売準備で確認した相違点

- **復元単位は玉川に限定する。** 工程②で酒蔵・小売の共有DB・アプリ・認証を確認した。今回の対象は玉川のみ。24表は構造一覧であり、全行置換する一覧ではない。玉川の親子行・共通マスター・採番条件を分け、桜浜・他社・酒蔵を保持する。詳細は [工程②の調査結果](phase2-investigation.md) を参照。
- **確認体制の現状と準備作業を分ける。** 現時点では体制未設置と回答済み。準備を継続し、実行・照合・復旧担当や承認済み状態を仮定しない。

- **会社ごとに入力原本が異なる。** 今回の玉川はTamagawaを使用する。桜浜はItaroへ直接入力するが、今回は取り込まない。調査記録は次回用に保管する。
- **管理場所と記録形式を区別する。** 玉川のTamagawaは入金用明細と残高クエリを使用する。確定請求・消込を推測で補わない。桜浜の会計原本確認は次回へ延期し、今回の工程②の完了条件には含めない。
- **保全不要は対象外データへ広げない。** 今回は玉川専用の既存実取引・設定に限定する。桜浜・他社・共有行・酒蔵・認証・監査証跡は保持する。現段階では削除・初期化を実行しない。

- **同じAccess形式でも構造は異なる。** Tamagawaの出荷ヘッダー・明細はItaroの酒蔵用項目と同一ではない。既存の酒蔵ステージング・差分適用をそのまま使わない。
- **Planにも書込みがある。** 酒蔵用 `Invoke-AccessDeltaMigration.ps1 -Mode Plan` は抽出・Aステージング・差分計画を行う。準備段階の単なる読取操作として呼ばない。
- **在庫不足許可と在庫非管理は異なる。** 現行小売の負在庫許可でも残数・移動は更新される。今回は玉川の非管理を会社別に対応し、他社設定は変更しない。
- **接続名が違っても同じDBを指し得る。** `retail` 接続は通常DB設定へフォールバックする。完全昇格時には酒蔵データも復元対象になり得る。
- **連携はHTTPだけではない。** 通常販売は内部サービスから酒蔵受注を作成する。ネットワーク遮断だけでは試験・取込の副作用を防げない。
- **履歴取込に通常販売処理を使わない。** 現在価格による再計算、小売在庫更新、酒蔵受注再作成を防ぐ専用処理が必要。
- **入金用の商品がある。** Tamagawaの商品ID=-1は入金用で、残高クエリでの扱いも確認した。同じ商品の小売独自商品フラグを外部商品の判定へ流用せず、通常売上・蔵受注から除外する。
- **発注先商品表は発注伝票と限らない。** 商品・価格の一覧を、そのまま数量を持つ注文へ変換しない。
- **原本の保存期間と移行期間は別である。** 2004年からの保存データを全量業務取込するとは決めず、酒蔵側と同じ期間・履歴区分にそろえる。
- **今回の試験対象外を成功扱いしない。** 実機・外部連携試験は利用者指定で対象外。内部判定の検証、外部送信の抑止、将来の本番条件と区別する。

詳細な根拠は [データ対応と実装課題](data-mapping.md) に記録する。新しい知見は「観測した環境・バッチ・差異・原因・再発防止・検証結果」を伴って追記する。
