## 商品表示の扱い

商品は販売SKU単位で1レコードとする。容量違い、スタイル違いは別商品として登録する。

発注・受注入力では、商品名だけでなく以下を並べて表示する。

| 表示項目 | DB |
| --- | --- |
| 銘柄 | `products.brand_name` |
| シリーズ | `products.series_name` |
| 容量 | `products.capacity_value` + `capacity_unit_id` |
| スタイル名 | `products.style_name` |

`style_name` は、火入、生、板粕、黒米、青磁、紺など、同じ銘柄・シリーズ・容量の中で商品を識別する短い名前として使う。容量や銘柄を `style_name` に重複して入れない。

## 入金の扱い

`review_required` はエラーではない。受領した金額を失わずに記録し、請求へ割り当てられなかった金額を要確認として残す状態である。

例: 請求残額11,000円に12,000円を登録した場合、11,000円を消込、1,000円を `unapplied_amount` に保存する。売掛を勝手にマイナスにせず、担当者が返金、次回請求への充当、手数料・値引等の適切な処理を選ぶまで保留する。

## 実装判断の手順

1. `current-state.md` で現行機能か未実装かを確認する。
2. `manifest.md` と領域別規約で業務要件を確認する。
3. 影響するService、migration、Feature Testを同じ変更単位で更新する。
4. 現行との差が残る場合は、この文書の表を更新する。
